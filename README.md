# I. Микрофронтенды для проекта mesto
В рамках задачи фронтенд проекта был разделен на микрофронтенды. Каждый микрофронтенд отвечает за определенную функциональность и способен развиваться независимо от других.

## Описание микрофронтендов
Проект состоит из следующих микрофронтендов:

1. **auth/** - Микрофронтенд для управления аутентификацией пользователей. Он включает компоненты для входа и регистрации пользователей.
   - **Компоненты:** 
     - `Login.js` - форма для входа пользователя.
     - `Register.js` - форма для регистрации пользователя.
     - `InfoTooltip.js` - компонент для отображения информации о статусе аутентификации.

2. **main/** - Основной микрофронтенд, который управляет отображением компонентов, включая хедер, футер и тело страницы между ними.
   - **Компоненты:**
     - `Header.js` - хедер.
     - `Footer.js` - футер.
     - `Main.js` - тело с содержимым.

3. **profile/** - Микрофронтенд, посвящённый управлению профилем пользователя.
   - **Компоненты:**
     - `Profile.js` - страница профиля пользователя.
     - `EditProfile.js` - форма редактирования профиля.

## Обоснование выбора подхода

Выбор MFA был сделан по следующим причинам:

1. **Масштабируемость**: Разделение на микрофронтенды позволяет командам работать автономно, независимо от других групп, что упрощает масштабирование разработки.

2. **Изолированность**: Каждый микрофронтенд функционирует независимо, что позволяет легко управлять изменениями, тестированием и развертыванием, минимизируя влияние одного изменения на другие части системы.

3. **Обновляемость**: При необходимости простого обновления или замены части приложения, микрофронтенды позволяют делать это без обширного рефакторинга всего проекта.

4. **Упрощение разработки**: Команды могут использовать разные технологии или стеки для разработки своих микрофронтендов, что даёт возможность выбора лучшего инструмента для задачи.

5. **Возможность повторного использования**: Модули поддерживают повторное использование кода и минимизацию дублирования.

## Описание микросервисов
Обновленная система управления торговыми площадками состоит из следующих микросервисов:

1. **API Gateway** - Единая точка входа для всех запросов, передает токен авторизации между сервисами, балансирует нагрузку и маршрутизирует запросы в нужные сервисы с транзитные данными, как например название товара и его описание
Стек: Node.js и Redis, что позволит быстро направлять запросы в сервисы и на время сохранять информацию для повторного предоставление, за счет чего снижается нагрузка на сервисы. 
При масштабировании возможно добавление балансировщика нагрузки Nginx

2. **Аутентификация и авторизация** - Сервис для регистрациии, аутентификации и выдачи ролей пользователям, а также генерации JWT-токена для авторизации пользователей при запросах в другие сервисы
Стек: Go и PostgreSQL дают высокую производительность
При масштабировании необходимо оптимизировать БД, добавив индексы и шардинг

3. **Профиль** - Сервис для управления услугами и товарами пользователя
Стек: Java и PostgreSQL аналогично сервису аутентификации
При масштабировании необходимо оптимизировать БД, добавив индексы и шардинг

4. **Заказы** - Сервис для управления заканными услугами и товарами
Стек: Python и PostgreSQL дают скорость в обработке асинхронных CRUD-операций
При масштабировании реплицировать БД на чтение и запись

5. **Аукционы** - Сервис для проведения аукционов по товарам пользователей 
Стек: Java и PostgreSQL аналогично сервису аутентификации
При масштабировании для частых обновлений ставок аукциона можно использовать Kafka
  
6. **Транзакции** - Сервис для уведомления пользователей об изменениях статусов заказа, аукциона и заявки поддержки
Стек: Node.js и MongoDB, так как нужна поддержка асинхронных запросов во внешние сервисы, mongo подходит для хранения событий - логов транзакций (идентификатор, статус, сумма)
При масштабировании можно перейти на хранение в очередях для асинхронной обработки транзакций

7. **Нотификация** - Сервис для уведомления пользователей об изменениях статусов заказа, аукциона и заявки поддержки
Стек: Python и PostgreSQL обеспечивают скорость доставки уведомлений
При масштабировании можно заменить хранение на очередь сообщений: RabbitMQ в реальном времени, далее при увеличении нагрузки можно перейти на Kafka

8. **Поиск и аналитика** - Сервис для поиска товаров и анализа успешности продаж
Стек: Scala и ClickHouse обеспечивают возможность быстрой обработки больших данных
При масштабировании возможен переход на Apache Spark, так как более производителен, чем Scala

9. **Поддержка** - Сервис для обработки заявок на поддержку пользователей по техническим вопросам и апелляциям
Стек: Go и PostgreSQL дают скорость в обработке асинхронных CRUD-операций
При масштабировании необходимо оптимизировать БД, добавив индексы и шардинг
